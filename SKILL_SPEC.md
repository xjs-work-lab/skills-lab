# Skill Specification

Each reusable Skill should define:

## Name

## Purpose
What capability does this Skill provide?

## Use when
Conditions that justify invoking the Skill.

## Do not use when
Boundaries that prevent over-application.

## Inputs
Required and optional inputs.

## Procedure
A compact, repeatable workflow.

## Outputs
Durable outputs or structured results.

## Quality checks
How to verify the Skill was applied correctly.

## Exit criteria
When the Skill is complete.

## Dependencies
Tools, sources, or other Skills required.

## Safety / privacy
Constraints on data, actions, or publication.

## Version notes
Meaningful changes to the Skill contract.

### Promotion rule
A one-off project procedure should normally remain project-local until it demonstrates clear reuse value across multiple contexts/repositories.
